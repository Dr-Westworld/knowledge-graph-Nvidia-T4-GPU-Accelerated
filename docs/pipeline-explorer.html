One physical GPU, two Python processes

The dependency boundary is Python-environment isolation; the resource boundary is shared GPU memory. Process A never imports vLLM. Process B never needs RAPIDS. They communicate through a localhost OpenAI-compatible API.

Every boundary has a contract

Allowed entity types

PERSON, ORGANIZATION, CONCEPT, PRODUCT, LOCATION, EVENT, LAW, METRIC, PROCESS, DOCUMENT, TECHNOLOGY, PROVISION.

Allowed predicates

regulates, requires, produces, located_in, depends_on, and the rest of the v1 ontology.

Bounded output

Maximum 20 triples per chunk; entity strings are bounded; exactly five fields are required per triple.

Why schema, not regex? The notebook records a regex grammar timeout. JSON Schema expresses the same ontology constraints through optimized enums and bounded arrays, and the smoke test verifies that the server actually enforces them.

Observed in the notebook

RAPIDS imports succeeded. The server became healthy in about 50 seconds. The plain request returned 386 characters in 9.1 seconds; the schema-constrained request returned valid JSON with two triples in 9.6 seconds.

Suggested code-reading order

  1. Start with the module header in kg_pipeline.py; it explains the process split and memory assumptions.
  2. Read PipelineConfig and the ontology constants to understand the operating envelope.
  3. Follow TextChunker → VLLMTripleExtractor → parse_json_triples → sitl_filter.
  4. Inspect resolve_entities_in_edges, the semantic/ANN resolvers, and then GPUGraphAnalyzer.
  5. Finish with export_to_parquet, LangfuseTracer, and VLLMMetricsPoller.
  6. Use scripts/test_vllm_server.py as the smallest executable contract for Process B.
